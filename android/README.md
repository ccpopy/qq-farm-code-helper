# 农场助手 Android

原生 Java / Material Components Android 应用，不依赖 Android Studio。
当前正式版本为 `0.1.2`（`versionCode 1002`），支持 Android 10 及以上。
[下载 Android 正式版](https://github.com/ccpopy/qq-farm-code-helper/releases/tag/android-v0.1.2)，
使用说明及限制见下文和 [Android 更新日志](CHANGELOG.md)。

## 构建与覆盖安装

需要 JDK 17、Android SDK 命令行工具、`platforms;android-36`、`build-tools;36.0.0` 和
`ndk;28.2.13676358`。首次下载依赖需要联网；不要把本机 SDK 或签名密钥提交到仓库。

在仓库根目录执行：

```powershell
.\scripts\build-android.ps1 -JdkDirectory $env:JAVA_HOME -SdkDirectory $env:ANDROID_HOME
.\scripts\build-android.ps1 -Install -DeviceSerial <已授权设备序列号> -AdbPath <adb路径>
.\scripts\build-android.ps1 -Configuration Release -Version 0.1.2 -Bundle
```

脚本验证固定的 hev-socks5-tunnel 2.19.1 AAR 的 SHA-256，并从固定提交和子模块构建
带本地补丁的四架构原生库，随后执行 lint 和 APK 构建。默认下载直连失败才使用 HTTPS
加速源。原生库验证源码版本、补丁与构建脚本的哈希以及生成 AAR 的 SHA-256，输入变化
必须重新构建。源码缓存和编译产物位于忽略目录 `outputs/android/native/`。APK 输出到忽略目录
`outputs/android/`。`adb install -r` 是覆盖安装，保留配置和本地证书；不要卸载或清数据。

### 固定应用身份与签名

应用名称固定“农场助手”，包名固定 `io.github.ccpopy.farmhelper`；不再交付带测试/诊断名称的并存包。
Debug 和 Release 共用长期保管的签名私钥，默认路径是
`%USERPROFILE%/.android/farm-helper/farm-helper.jks`（本机 `C:/Users/13434/.android/farm-helper/farm-helper.jks`）。
该文件是此前安装签名密钥的保留副本，别名沿用 `androiddebugkey`，保留原签名以支持覆盖安装。
签名配置保存在同目录的 `signing.properties`，口令不进入源码；可用 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、
`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 指向同一密钥的安全备份。

预期证书 SHA-256 为 `cf51c2ee1ed4870e98751894f41cb5406b7f2cd29645df2fa5186f829235c749`。
Gradle 校验私钥存在、证书指纹和包名，构建脚本再次检查 APK 包名、名称与实际签名；不匹配就失败，

## 使用与安全边界

界面分为“获取 / 账号 / 日志 / 设置”四页：

- 获取页顶部切换 QQ / 微信。QQ 使用中央按钮启动或停止 VPN 获取；微信默认是扫码登录，
  可改用实验性的 VPN 获取。缺少服务器配置或证书时页面顶部给出入口，证书在设置页“抓包证书”中管理。
- 收到身份或好友数据后（或手动导入后）按设置自动比对服务器同平台账号：自身 GID 相同的账号提示“检测到已有账号”，
  其次提示上次推送的账号；否则由用户选择新增或覆盖已有账号。任何写入都需要用户确认。
  推送内容（Code、好友）和是否自动比对在设置页“推送”中开关，默认全部开启。推送 Code 后自动检查账号是否上线。
- 设置页开启“悬浮窗”并允许系统的“显示在其他应用上层”权限后，VPN 运行时可在 QQ 中查看结果、
  选择账号并推送，也可新增账号、清除结果继续换号。悬浮窗可拖动和收起，关闭悬浮窗不停止 VPN。
- 账号列表和推送确认优先显示服务器已有的 QQ 号（`uin` / `qq`），不把服务器内部 ID 或农场 GID 当作 QQ 号。
  当前后台账号列表不提供自身 GID；首次选择账号成功同步 Code 后，助手在本机记录对应关系，后续同一 GID 可匹配。
  绑定按服务器、账号 UUID、平台及 QQ 号隔离；只有 Code 没有身份时仍需选择或确认目标账号。无需修改 main 后台。
- 账号页自动读取服务器账号并逐个检查在线状态。“掉线提醒”开关与账号选择相互独立：铃铛或“全选”选择账号，
  开关开启且至少选中一个账号时才运行提醒服务；未选择账号等同于不提醒。通知栏“停止”会同时关闭开关。
- 设置页“悬浮窗”开启后（需系统悬浮窗权限），在游戏里以小悬浮球常驻：点开是一张紧凑的半透明卡片，
  可直接开始/停止 VPN、查看 Code 与好友数量、同步或清除结果；在助手自身界面前台时自动隐藏。
  窗口由独立前台服务 `OverlayService` 托管，停止 VPN 后仍可用来重新开始获取。
  通知中的“停止”只关闭悬浮窗；关闭悬浮权限后服务也会停止。
- 设置页“允许截图”默认关闭（`FLAG_SECURE`，截屏与录屏为黑色）；开启后应用画面可正常截屏。

1. 在设置页填写自己的 Node 部署服务器 URL 和管理 API Token，“保存并测试”。
2. 设置页“透传诊断”可先确认农场能正常进入；此模式不解密，也不会获取 Code。
   切换应用会清除内存结果及已选推送账号；运行中的 VPN 须先停止。
3. 获取模式需要用户手动生成、导出并在系统安装本机 CA。安装 CA 不代表所选应用一定信任；
   不修改 QQ / 微信、不 root、不绕过证书固定或 TLS 校验。
4. 用户授权 VPN 后，仅将所选应用的新 TCP/UDP 流量送入本机转发，包括 DNS；
   不按固定网关 IP 筛选入口，不要求重启 QQ / 微信。获取模式只解密精确的农场目标 SNI，
   其他连接原样转发。VPN 不设运行总时限；获取完成、推送和清除结果均不结束 VPN。
   手动停止、系统撤销授权或其他 VPN 接管时结束；系统结束应用进程也会中止服务。
   好友分批到达即可同步已收到的部分，后续回包继续补充待同步好友。清除结果后进入下一轮，不接收上一轮迟到数据。
5. Wi-Fi 可能只有 IPv4，蜂窝网络也不保证支持 IPv6。以当前默认互联网连接为准，
   检测 IPv6 地址及默认路由，跟随网络变化重新配置路由、DNS、MTU 和受保护套接字。
   不强制开关 Wi-Fi、移动数据，也不主动选用备用蜂窝网络。
6. 获取后核对账号再推送；已有账号按服务器返回的 ID 更新，不按备注猜测。
   有自身 GID 时阻止更新身份不匹配的服务器账号。好友同步为增量追加。
   新账号备注会附显式随机后缀，避免上游同名创建变成覆盖已有账号。
7. 服务器接受更新和账号真正在线是两件事，可分别查看结果并检查登录状态。

### 微信扫码登录与手机通知

- 覆盖安装保留 `local-ca.cer` 和 Android Keystore 中的 `farmhelper.local-ca.rsa.v1` 私钥，已安装的 CA
  无需因应用更新重新安装。不要卸载或清除数据后再安装，否则应用私钥会丢失，系统中的旧 CA 无法代替私钥。

- “微信扫码登录”页默认新增账号（点“登录到”可改为已有微信账号），新增时询问账号备注。
  “获取二维码”会先将图片发布到 `Pictures/FarmHelper` 相册，然后使用微信注册的
  `ShortCutDispatchAction` / `launch_type_scan_qrcode` 快捷方式，再在电脑或另一台设备展示图片。
  本机实测微信拒绝从相册识别此类登录码，提示必须使用摄像头扫描；仅保存图片不能保证在同一台手机完成登录。
  应用不显示二维码、不自动确认授权；快捷入口不可用时退回微信并提示手动操作。
- 扫码任务在返回助手和界面重建期间保留在内存中；进程结束后需重新获取。二维码有效期由服务器决定。
  状态查询遇到 DNS、连接中断、超时或临时 HTTP 错误时，保留原任务并退避重试，直到服务器规定的有效期。
  Token、TLS 证书错误和任务失效仍终止；账号提交不会自动重试。
  微信确认应用宝授权后，返回助手确认目标账号，再换取农场 Code 并提交 `wxLoginTaskId`，保留服务端刷新会话。
  新账号使用随机备注后缀，已有账号按 ID 更新。提交结果不明确时不自动重试，防止重复创建。
- 保存后检查账号连接，通过服务器 `/api/friends` 读取微信游戏好友 GID；不把微信 openid 当作 GID。
  返回 0 个好友时明确提示尚不能证明好友读取成功。该方式不依赖手机 VPN 或本地 CA。
- 账号页开启通知服务后，优先订阅自己的服务器 `/api/mobile/offline-events`。需部署 qq-farm-bot main
  分支的手机通知中转接口；旧服务器返回 404 时回退为原有“两次离线”轮询。
  通知绑定服务器配置、账号 ID 和 UUID，点击后核对目标账号；微信可直接进入扫码续登页。
  停止服务或应用被系统结束后不接收新通知，不自启；省电与网络中断可能延迟通知。

### 微信 VPN 接入（实验性）

- 选择微信后，VPN 仅接管 `com.tencent.mm`；QQ 使用 `com.tencent.mobileqq`。启动按钮、
  应用入口、系统 VPN 会话、通知和日志均展示所选应用。服务启动时固定本次平台，网络重建不改变它。
- QQ 沿用原有同时读取好友选项；微信默认只截取 Code，阻止该次小游戏登录先消费 Code。
  微信可在设置中改为单独读取好友：放行登录、等待农场好友回包，但不将已转发的 Code 暴露为可推送结果。
  两个平台分别记忆好友选项。微信 TLS、登录 Code 可用性及好友回包格式仍待真实验证，不能将入口接入视为抓取成功。
- 微信小游戏的同玩好友授权由小游戏自身处理。微信 `openid` 与农场 `gid` 不同，助手只接受
  已识别农场回包中的 GID 或用户手动导入的 GID，不读取微信通讯录，也不把 `openid` 转成 GID。
  目前复用的农场解析器仍须通过微信实际回包验证，不新增猜测字段或向微信请求好友授权。
- 本次结果携带不可变平台标记；账号列表按平台筛选，新增 / 更新发送 `qq` 或 `wx`，
  服务端平台与结果不一致时阻止 Code 和好友同步。手动导入明确展示当前平台，离线提醒可切换至账号对应平台。
- 平台回归用隔离设置及本机模拟服务器测试，不接触真实账号。按照本分支已有约定，
  真机测试类留在忽略的 `app/src/androidTest/`，本地诊断构建脚本留在 `outputs/android/qa/`，
  不随正式应用打包。

### 转发限制审计

- 移除助手的 48 条 SOCKS 连接、160 个工作线程、64 条原生会话和 64 条 UDP 映射上限。
  原生 `max-session-count: 0` 表示不设置数量上限；实际容量仍受设备资源约束。
- 移除 Java UDP 映射的 20 秒空闲删除、已建立 TLS 转发的 25 秒读超时，以及好友回包的
  20 秒等待上限。映射随 SOCKS 控制连接关闭、底层网络变化或 VPN 停止释放。
- 未识别或超出检查缓冲范围的 ClientHello 原样透传，不因无法解析 SNI 阻断其他连接。
  好友 GID 不再截取前 500 个；检查间隔接受正整数秒，不再强制限制为 30–900 秒。
- 保留连接建立、SOCKS 认证、TLS 握手和 HTTP 头读取的失败超时；它们不限制已建立连接
  的总时长。保留按应用接管、回环代理认证、证书与主机名验证、凭据过期及解析缓冲边界。
  更新包的大小、签名和摘要检查，以及 API 响应大小和日志容量限制仍用于防止内存耗尽或
  凭据暴露，不参与 QQ 流量准入。仅 Code 模式仍会中止该次官方登录，避免先消费 Code；
  0.1.1 起获取完成后保持 VPN，清除结果可开始下一轮；透传诊断不获取凭据。
- 原生 TCP 的 300 秒和 UDP 的 60 秒空闲回收也已禁用。应用明确配置
  `tcp-read-write-timeout: 0` 和 `udp-read-write-timeout: 0`；本地补丁使解析器接受 0，
  转换为核心已有的 `-1` 无限 I/O 等待。停止会话仍使用 0 并唤醒任务，因此手动停止、
  网络变化及连接关闭仍可释放资源。正数超时和连接建立超时的语义保留。
  补丁见 `native/disable-idle-timeouts.patch`，固定源码版本见 `native/tunnel-build.json`；
  `scripts/build-android-tunnel.ps1` 生成 `hev-socks5-tunnel-2.19.1-farm1.aar`，不改动原始上游 AAR。
  原生等待逻辑已在 Android 真机验证：TCP/UDP 均空闲等待超过 310 秒，显式唤醒后可继续
  等待，停止能及时取消；正数超时对照及配置继承、覆盖行为也通过检查。

应用可移除本地 CA/私钥；系统已安装的 CA 必须由用户在 Android 的凭据设置中移除。
卸载应用或删除本地 CA 不会自动删除系统证书。请对照证书名称和指纹操作。

## 权限

- 网络和网络状态：连接用户服务器、转发所选 QQ / 微信流量、检查更新、识别底层网络。
- VPN：由系统单独确认；会替换当前运行的其他 VPN。
- 前台服务：VPN/用户启用的账号检查各有持续通知和停止操作。
- 通知：显示获取结果、账号连续离线或服务器 Token 失效；可拒绝或撤销。
- 安装未知应用：仅在用户下载并选择安装更新时交给系统授权，不静默安装。
- 不申请通讯录、聊天读取、无障碍服务、root 或广泛存储权限。

## 服务器离线提醒

适用于 Node 直接部署，不依赖 Docker。当前使用用户明确启用的服务器状态轮询，
默认 60 秒、连续两次有效离线结果才提醒。断网/请求失败会重置计数；401/403
表示管理 Token 失效，不伪报游戏账号掉线。休眠与省电限制可能延迟提醒。

上游有 webhook，但手机通常没有公网入站地址，而且通知载荷缺少可靠账号 ID。
第三方通知中转、锁屏实际投递和后台长时间稳定性暂不视为验收通过。

## 更新与正式发布规范

Android 更新只识别 `android-vX.Y.Z` 的非草稿、非预发布 GitHub Release，资产名必须是
`QQFarmCodeHelper-android-vX.Y.Z.apk`。下载验证资产 SHA-256、包名、版本、递增
versionCode 和 APK 签名，随后由用户确认安装。更新源不接收服务器 Token 或 Code。
加速源仍须 HTTPS；它影响可用性与隐私，不能替代 APK 签名验证。

正式发布继续沿用上述固定签名密钥；可通过环境变量指定同一私钥的安全备份。
不要更换签名身份、生成临时密钥或把密钥提交源码。
创建 Android Release 时设置 `make_latest: false`，避免影响桌面应用的 latest 更新通道。
未获得发布授权不创建 Release，也不为测试增加版本。

### 标签驱动的 Actions 发布

`.github/workflows/release-android.yml` 在推送 `android-vX.Y.Z` 标签时构建 APK 和 AAB，
从标签设置 `versionName`，按 `major * 1000000 + minor * 1000 + patch` 生成递增的
`versionCode`（minor、patch 各不超过 999）。本地不传 `-Version` 时使用 Gradle 中的当前版本。
先更新 `android/CHANGELOG.md` 对应标签的条目，再提交并打标签；发布说明来自这个条目。

仓库 Actions Secrets 需配置原有签名材料：`ANDROID_KEYSTORE_BASE64`、
`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS` 和 `ANDROID_KEY_PASSWORD`。
Base64 只是密钥文件的传输编码，只能放在加密 Secret 中。缺少原密钥或签名不匹配时构建失败。
工作流验证 APK/AAB 签名，全部产物上传到草稿后才公开正式 Release，并保持桌面 latest 不变。

发布资产为 `QQFarmCodeHelper-android-vX.Y.Z.apk`、同名 `.aab` 和 `SHA256SUMS.txt`。
APK 可直接安装；AAB 是分发平台输入，不能直接安装。混淆映射作为 Actions 构建产物保留。
源码中不提交 APK、AAB、原生库构建产物或签名私钥。
